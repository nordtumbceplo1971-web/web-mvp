## 全栈 Serverless 化 v0.1.2（同一日 11:40）

**背景**：用户已把前端部署到 Vercel（GitHub 集成），但后端未部署 → `/api/health` 404 → 侧栏「服务未连接」。

**方案**：同一 Vercel 项目一体化托管 —— 静态前端 (`frontend/dist`) + `/api/*` Serverless Function
（根目录 `api/[...path].js`）。**用户只需把 Vercel 的 Root Directory 从 `frontend` 改为仓库根 `/`**，
其余（build / output / install / functions）已写进 `vercel.json`。

**Serverless 适配的 4 个真坑（务必记住）**：
1. **MOCK 任务必须有状态**：原本进度依赖内存 + works.json，冷启动后轮询永远 pending →
   改为 taskId 自描述 `mock-{type}-{count}-{ts36}-{uuid}`，`parseMockTaskId()` 解析出 created_at，
   进度纯函数 → 跨实例正确推进（已用「构造一个无作品记录的旧 taskId」验证通过）
2. **文件系统只读**：works.json 写不进去 → 三级降级 `WORKS_DATA_DIR` → `backend/data` → `/tmp/brandstudio-data` → 内存
3. **反向代理协议**：`req.protocol` 在代理后是 http → 占位图 URL 变 http 被浏览器按混合内容拦截 →
   必须读 `x-forwarded-proto` / `x-forwarded-host`
4. **静态目录归属**：函数只接管 `/api/*`，`/mock-assets` 要复制到 `frontend/public/` 由静态托管

**新增验证工具**（可复用）：
- `tools/page-check.mjs`：CDP 体检（Node 22 内置 WebSocket 驱动本机 Edge），查溢出/报错
- `tools/vercel-sim.mjs`：本地以 Node 模拟 Serverless 调用，验证 `api/[...path].js` 的路径还原
- `tools/smoke.mjs`：端到端冒烟（健康检查/模板/素材/生成轮询/入库），`BASE_URL` 可指向任意环境

**注意**：Edge headless 的 `--window-size=375` 有最小窗口宽度限制，直接 `--screenshot` 会截断；
真实 375px 验证必须用 CDP `Emulation.setDeviceMetricsOverride`。

已推送到 GitHub（commit `12fce9c`）。

## v0.1.7 修复与重新推送（同一日 14:00）

### 核心发现：v0.1.6 的「后端地址可配」只做了一半

v0.1.6 改了 `api.js` 让请求走可配地址，**但漏掉了 `ui.js` 里 `pollTask()` 写死的
`fetch('/api/tasks/...')`**。后果：

| 部署形态 | 模板库 | 任务轮询 | 结果 |
|---|---|---|---|
| 同域（Vercel 一体化） | ✅ | ✅ 同域 | 正常（所以之前没暴露） |
| 分开部署（设置里填地址） | ✅ 打配置地址 | ❌ 仍打同域 `/api` | **永远转圈不出图** |

即：v0.1.6 主打的「前后端分开部署」场景，生成流程根本走不通。旧 `pollTask` 又把异常吞掉、
当作「还在处理中」，所以既不报错也不退额度。

### 实测复现方法（关键经验）

用**静态构建产物 + 独立后端**才能复现 —— dev 模式有 vite 代理，会把同域 `/api` 转发到后端，
从而掩盖这个 bug。复现步骤：
1. `npx serve -s frontend/dist -l 4300`（静态托管，无代理）
2. 后端 `CORS_ORIGIN=http://127.0.0.1:4300 npm start`（8787）
3. 页面里 `localStorage.setItem('bs-api-base','http://127.0.0.1:8787')`
4. 旧代码：轮询 14 次全落在 `http://127.0.0.1:4300/api/tasks/...`，无结果
   修复后：轮询 4 次全落在 `http://127.0.0.1:8787/api/tasks/...`，正常出图

**教训**：验证「地址可配」类功能，必须用静态产物 + 独立 origin 测，dev 代理会掩盖问题。

### 推送时的坑：远程有一条「影子提交」

本地 `83cdee9`(v0.1.6) 与远程 `f832738`(v0.1.6) 的 **tree 与 parent 完全相同**，只有 commit
message 末尾差一个换行 —— 是之前走 `tools/push-via-api.mjs` 兜底通道时用 API 重建提交留下的
（时间戳/换行导致 SHA 不同）。两者内容零差异（`git diff HEAD origin/main` 为空）。

处理方式：`git rebase --onto origin/main 83cdee9 HEAD` 把新提交摘到远程提交之上，
再 `git branch -f main <new>` + `git checkout main`（rebase 后 HEAD 是 detached）。
之后就是干净的 fast-forward push。

**推完必须独立验证远程内容**（不能只看 push 输出）：
`git ls-remote origin refs/heads/main` 比对 SHA + 用 GitHub API 读回文件内容。

### 「影子提交」的真正成因（已修复 tools/push-via-api.mjs）

之前那条影子提交不是玄学，是 API 兜底脚本的两处细节：

1. **message 用了 `git log -1 --format=%B`** —— `%B` 会比原始 commit 对象多补一个结尾换行
   （实测 raw len=28 / %B len=29），重建出的 SHA 因此和本地不同。
   改为 `git cat-file commit HEAD` 取原始对象里的 message（去掉 header 到空行那段）。
2. **日期去掉了时区冒号**（`+08:00` → `+0800`）—— GitHub API 要求严格 ISO 8601，
   去掉冒号直接 422 `is not a valid date-time`。改为原样传 `%aI` / `%cI`，
   GitHub 会自己转成 git 内部的 `+0800`，SHA 依然与本地一致。

修正后 API 推送产出的 SHA 与本地**完全相同**（实测远程 `df2a747` == 本地 `df2a747`），
不会再产生影子提交。

### 代理彻底不可用时的兜底

本次 github.com:443 一度完全连不上（`api.github.com` 正常），git push 连试 4 次全失败。
此时用 `node tools/push-via-api.mjs` 走 API 通道推送即可（凭证从 git credential helper 取，
不落盘）。等 github.com 恢复后再用普通 git push 补上后续提交。
